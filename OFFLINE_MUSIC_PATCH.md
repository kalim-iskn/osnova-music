# WaveFlow: офлайн-треки и экран блокировки iPhone

## Что входит

- В **«Мои треки»** (лайкнутые треки) есть отдельная кнопка скачивания каждого доступного файла. Кнопка с галочкой удаляет локальную копию после подтверждения. Никаких автоматических загрузок нет.
- Аудиофайл и данные трека сохраняются в **IndexedDB данного браузера** под ID авторизованного пользователя; на сервер новые файлы не загружаются. Скачанное отображается независимо от текущей страницы пагинации.
- `/offline.html` — автономный плеер скачанных треков. Service Worker сохраняет саму страницу и нужные иконки при первой установке и выдаёт локальное аудио с поддержкой `Range` (`206 Partial Content`). После первоначальной установки и загрузки музыки страница доступна без сети.
- Добавлены PWA manifest и иконки. После установки на домашний экран iPhone офлайн-плеер можно открыть из приложения.
- Media Session показывает название, исполнителя, альбом и обложку, передаёт команды Play/Pause, Next/Previous и перемотку через `seekto`, если они поддерживаются ОС.
- Laravel-прокси аудио передаёт запросы `Range` источнику и возвращает корректные `206`/`Content-Range`.

## Установка

Из корня **той же версии проекта, что в архиве `osnova-music-master.zip`**:

```bash
git apply --check waveflow-offline-ios.patch
git apply waveflow-offline-ios.patch
npm ci
npm run build
npm run test:offline
```

Задеплойте обновлённые PHP, Vue, JS, HTML, manifest и PNG-файлы из `public/`. Необходимо **HTTPS** (или localhost при локальной разработке), и веб-сервер должен отдавать `/sw.js` из корня сайта с JavaScript MIME-типом; `/offline.html`, `/icon-192.png`, `/icon-512.png` и `/site.webmanifest` — как обычные статические файлы. Перезагрузите сайт на iPhone после деплоя.

## Ручной сценарий проверки

1. Войдите, откройте **«Мои треки»**, нажмите кнопку скачивания возле 2–3 треков и дождитесь галочки. Проверьте счётчик скачанных и `/offline.html`.
2. Включите авиарежим/отключите Wi-Fi и сотовую сеть, **полностью перезапустите** установленный на домашний экран сайт и откройте скачанные треки. Проверьте проигрывание, перемотку, следующий и предыдущий треки.
3. С заблокированным экраном проверьте системные кнопки, название и обложку. Убедитесь, что звук продолжается после блокировки. Проверьте очередной трек после окончания предыдущего.
4. Снова включите интернет и удалите локальную копию через кнопку с галочкой.

## Ограничения

- Это браузерное хранилище конкретного устройства и браузера, **не синхронизация** между устройствами. iOS может очистить его при нехватке места или при очистке данных сайта. Экспорт на Files здесь не реализован.
- Для офлайн-прослушивания нужно **один раз открыть сайт с интернетом**, дать Service Worker установиться и вручную скачать MP3. Неподдерживаемые браузеры и приватный режим могут блокировать хранилище.
- Музыка скачивается через существующий endpoint `/tracks/{id}/stream`. Если источник Muzofond недоступен, вернул редирект на другой домен или не отдаёт полный аудиофайл, скачивание не выполнится (будет сообщение об ошибке).
- Обложки сохраняются с музыкой, **если источник картинки разрешает CORS**. Иначе офлайн-плеер покажет запасную обложку. На экране блокировки при наличии сети используется исходный URL обложки. Для гарантированной загрузки всех сторонних обложек нужен отдельный безопасный серверный image-proxy.
- iOS/WebKit могут по-разному рисовать системные кнопки управления и ограничивать автоматическое начало следующего трека после блокировки. Наличие Media Session API **не гарантирует** идентичного Apple Music интерфейса.
- Это реализация на основе исходного архива; сборка Vite и проверка на физическом iPhone не выполнялись в окружении создания патча. Автоматически проверены JS/PHP синтаксис, IndexedDB-операции на тестовом адаптере и логика SW с HTTP Range.
